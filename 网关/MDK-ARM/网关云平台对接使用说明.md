# 网关云平台对接使用说明

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v3.0 |
| 面向对象 | 云平台开发 / 对接集成方 |
| 适用范围 | 网关北向（云平台侧）MQTT 接口 |

> 本文描述云平台与网关之间的接口约定（连接、主题、报文、命令/应答、事件、错误码与典型流程）。
> 射频侧（网关与现场子设备之间）的约定不在本文范围内。

---

## 1. 概述

网关作为现场中心节点，上电后通过 4G 连接云平台指定的 MQTT 服务器，对云平台采用
**「命令下行 — 应答返回 + 事件/遥测上报」** 的交互模型：

- **下行**：平台向命令主题发布 JSON 命令；
- **应答**：网关对每条命令回一条应答（携带 `code`，表示受理/执行结果）；
- **上行**：网关按周期或事件向遥测、事件、状态主题发布 JSON。

云平台需要订阅上行的 **命令应答 / 事件 / 遥测 / 状态** 主题，并向 **命令主题** 发布命令。

---

## 2. 连接约定

| 项目 | 说明 |
| --- | --- |
| Broker 地址 | 由网关配置项 `network.host` / `network.port` 指定；网关开机时据其建立连接 |
| ClientId | 等于网关 ID（`gwId`） |
| 用户名 | **出厂为 `tuguan`**，与 `gwId` **无关**，由配置项 `network.username` 指定 |
| 密码 | 由配置项 `network.password` 指定。**`cfg.query` 读取时固定返回 5 个 `*` 掩码**，不返回明文，也不返回真实长度 |
| 网关 ID（gwId） | 网关唯一标识，**26 位十六进制字符串，首字节为 `11`**。出厂写入，可用 `cfg.set` 的 `system.gwId` 修改；修改后在下次建立连接时生效，并体现到全部主题中 |
| 应用层鉴权（auth） | 可选。启用后，下行命令必须携带正确 `auth`，否则应答 `1008` |

> 网关与平台的连接参数属于配置项，变更后**重启生效**（见 §9.2 的 `network` 域说明）。
> **当前版本暂不支持 TLS**（配置项 `network.tls` 恒为 0），平台侧请提供明文 MQTT 接入端口。

## 3. 主题约定

所有主题均以网关 ID（`gwId`）为标识，`{gwId}` 需替换为实际网关 ID。

| 主题 | 方向 | 说明 | QoS | retained |
| --- | --- | --- | --- | --- |
| `rt/gw/{gwId}/cmd` | 平台 → 网关 | 下行命令 | 1 | 否 |
| `rt/gw/{gwId}/cmdresp` | 网关 → 平台 | 命令应答 | 1 | 否 |
| `rt/gw/{gwId}/telemetry` | 网关 → 平台 | 水位遥测 | 1 | 否 |
| `rt/gw/{gwId}/event` | 网关 → 平台 | 事件（含事件补报、升级进度） | 1 | 否 |
| `rt/gw/{gwId}/status` | 网关 → 平台 | 状态 / 心跳 | 1 | 是 |
| `rt/gw/{gwId}/lwt` | 网关 → 平台 | 掉线遗嘱 | 1 | 是 |

**说明：**

- **所有主题一律 QoS 1**（含 `telemetry`）。网关每次发布都等 broker 的 PUBACK，
  平台看到即代表 broker 已接收；QoS 0 会造成"网关以为发了、平台没收到"。
- `status` 采用 retained，平台只要订阅即可在任意时刻拿到网关最近一次的在线状态；
- `lwt` 为**独立的掉线通知主题**（retained）。平台若需感知网关掉线，需**额外订阅该主题**；
- 命令主题仅接受 JSON 文本；不符合格式的下行会被丢弃。

## 4. 报文格式

### 4.1 下行命令信封

```json
{
  "cmd": "sen.bind",
  "msgId": "f4-01",
  "ts": 1690000000,
  "auth": "xxxx",
  "data": { }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `cmd` | string | 是 | 命令名，见 §12 |
| `msgId` | string（≤16 字节） | 建议 | 命令唯一编号，应答原样回带，用作幂等键 |
| `ts` | uint32 | 否 | 平台 Unix 秒 |
| `auth` | string | 视配置 | 应用层鉴权口令（启用鉴权时必填） |
| `data` | object | 视命令 | 命令参数 |

### 4.2 应答信封

```json
{
  "cmd": "sen.bind",
  "msgId": "f4-01",
  "code": 0,
  "msg": "ok",
  "ts": 1690000001,
  "data": { }
}
```

| 字段 | 说明 |
| --- | --- |
| `cmd` / `msgId` | 原样回带请求中的对应字段 |
| `code` | 结果码，`0` = 成功；非 0 见 §13 |
| `msg` | 结果码对应的英文短描述 |
| `ts` | 网关当前 Unix 秒 |
| `data` | 随命令而定，可为空对象 `{}` |

### 4.3 上行事件信封

```json
{
  "event": "status.report",
  "msgId": "h001",
  "ts": 1690000002,
  "data": { }
}
```

### 4.4 幂等（重要）

网关会记住**最近处理过的 `msgId`**（时间窗口 **60 秒**）。
窗口内若收到**相同 `msgId`** 的命令，网关**不会重复执行**，而是**直接重放上一次的应答**。

> 平台在弱网下重发命令时，**务必复用同一 `msgId`**，即可安全获得同一份应答。

## 5. 设备绑定

### 5.1 绑定流程

绑定采用**配对窗口**方式：平台发起绑定命令 → 网关打开一个配对窗口 → 窗口内现场子设备进入配对
→ 网关完成握手、将该设备写入配置 → 结果**异步**上报平台。

| 命令 | 适用设备 |
| --- | --- |
| `sen.bind` | 液位传感器 |
| `dev.bind` | 联动设备（声光 / LED / 一体机） |

> **设备标识（uid）**：本网关使用 **13 字节（26 位十六进制大写）** 的唯一 ID 寻址，
> 形如 `21A1B2C3D4E5F60718293A4B5C`。绑定结果及后续所有按设备寻址的命令
> （`sen.set` / `dev.set` / `dev.ctrl` / 解绑等）均使用该 `uid`。

**设备 ID 前缀（首字节）含义：**

| 前缀 | 设备类型 |
| --- | --- |
| `11` | 网关（即 `gwId`，前两字符同为 `11`） |
| `21` | 液位传感器 |
| `31` | 声光报警器 |

> **注意：早期对接版本使用的 3 字节设备 ID 已不再支持**，请统一按 13 字节（26 位 hex）格式对接。

### 5.2 命令参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 否 | 设备名称，绑定成功后写入该设备的 `name` |
| `pairWindowSeconds` | uint16 | 否 | 配对窗口时长（秒），默认 `60`，**允许范围 1~300**，越界回 `1001` |
| `serial` | **已弃用** | 否 | 该字段**已弃用但保留**：可以不传；传了只作备注存储（不参与绑定判定），超长仍回 `1001` |
| `type` | uint8 | **仅 `dev.bind` 必填** | ★2026-11-03 统一★ `1` = 液位（UID 21）/ `3` = 一体机·声光（UID 31）。缺失、`2` 或其它值回 `1001` |

### 5.3 应答

成功受理返回 `code = 0`，`data` 为：

```json
{ "pairWindowSeconds": 60 }
```

> **注意：`code = 0` 仅表示「配对窗口已开启」，并不代表绑定已经完成。**

### 5.4 绑定结果（异步事件）

真实绑定结果通过 **`event.device`** 事件上报：

| `data.event` | 含义 |
| --- | --- |
| `bound` | 绑定成功 |
| `bind_failed` | 绑定失败（如窗口内未完成握手） |

`data` 字段：`uid`（设备唯一 ID）、`devType`（`sensor` / `device`）、`event`、`serial`（有则带）。

### 5.5 其他返回码

| 情况 | code |
| --- | --- |
| 设备数量已达上限（液位 / 联动各自上限 5 台） | `1009` |
| `dev.bind` 缺 `type` 或取值非法 | `1001` |
| 网关设备侧配对通道不可用 | `1006` |

**绑定完成后**：该设备进入配置的 `sensors[]` / `devices[]`，可用 `sen.query` / `dev.query` 查看；
其 `uid` 用于后续一切按设备寻址的命令（`sen.set` / `dev.set` / `dev.ctrl` / 解绑等）。

## 6. 设备解绑

| 命令 | 适用设备 |
| --- | --- |
| `sen.unbind` | 液位传感器 |
| `dev.unbind` | 联动设备 |

**参数**：`uid`（string，必填，必须是已绑定的设备）。

**流程**：网关向该设备下发解绑 → 收到设备确认后删除该设备配置 → 通过 **`event.device`**
（`data.event = "unbound"`）上报平台。

**应答**：成功返回 `code = 0`。

> **注意：`code = 0` 仅表示「解绑请求已受理」，真正完成以 `event.device{unbound}` 事件为准。**

| 情况 | code |
| --- | --- |
| `uid` 未绑定 | `1003` |
| 已有解绑正在进行 | `1006` |
| `uid` 非法 / 缺失 | `1001` |

## 7. 档位调节

### 7.1 档位与状态定义

网关固定使用 4 个档位，与水位状态一一对应（不可配置）：

| 档位 | 状态 | 水位条件 |
| --- | --- | --- |
| `0` | Resolved | level ≤ `resolveCm` |
| `1` | Normal | `resolveCm` < level ≤ `warningCm` |
| `2` | Warning | `warningCm` < level < `alarmCm` |
| `3` | Alarm | level ≥ `alarmCm` |

阈值（单位 cm）在 `thresholds` 域配置，出厂默认：`alarmCm=10`、`warningCm=7`、`resolveCm=2`。
另有防抖参数 `confirmCount`（连续确认次数）与事件去抖 `minChangeCm` / `eventMinIntervalSeconds`。

### 7.2 两种工作模式

| 模式 | 说明 |
| --- | --- |
| **自动（`auto`，出厂默认）** | 网关按水位自动评估状态、自动切换档位并下发联动，无需平台干预 |
| **手动（`manual`）** | 平台通过 `dev.ctrl` 直接指定档位执行；进入手动后，阈值变化不再自动联动；`manualTimeoutSeconds` 到期后自动回到 `auto` |

### 7.3 手动档位调节（`dev.ctrl`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `uid` | string | 是 | 目标设备 `uid`（26 位 hex），或字符串 `"all"`（全部启用的联动设备） |
| `gear` | uint8 | 是 | 目标档位 `0` ~ `3` |
| `ledText1` / `ledText2` | string | 否 | 覆盖 LED 两个半屏文本；支持 `{level}` 占位符 |
| `ttsText` | string | 否 | 覆盖语音文本，空串表示不播报 |
| `ledShowMode` | uint8 | 否 | `0` 横屏 / `1` 竖屏 |
| `ledTextShowMode` | string | 否 | 两个半屏的对齐，形如 `"1,0"`（`0` 居中 / `1` 对齐） |
| `ledColor` | string | 否 | 两个半屏的颜色，形如 `"red,yellow"`（取值 `off` / `red` / `green` / `yellow`） |

> 文本类字段的语义：**字段未出现 → 留空（什么都不下发）**；**字段出现（含空串）→ 原样使用，空串即空**。
> 网关**不会**再用档位模板去补未出现的字段 —— 档位模板只在边缘联动（本地按水位自动触发）那条路径使用。

**应答 `data`：**

```json
{
  "results": [ { "uid": "31....", "code": 0 } ],
  "configVersion": 7
}
```

- `results[].code` 反映**受理投递结果**：`0` = 已受理下发；`1003` = 目标设备不存在 / 已停用；`1007` = 网关内部错误；
- **真实空口执行结果（成功 / 超时 / 重试）由 `event.action` 异步上报**（见 §8.2）；
- 执行成功后网关进入 `manual` 模式。

### 7.4 档位动作定义（`rule.set`）

`rule.set` 用于配置**每个档位的联动动作内容**（`gears` 数组，按 `gear` 字段定位对应档位）：

- 参数只允许包含 `gears` 域；若同时夹带其它配置域，回 `1001`（不静默忽略）；
- 每档可配置：目标设备（`all` 或指定 `uid`）、声光模式、LED 显示（横/竖屏、对齐、颜色）、
  LED 两段模板文本、语音模板文本；
- 文本模板支持 `{level}` 占位符（替换为当前水位 cm 整数）；
- 应答 `data.configVersion`。

`rule.query` 返回 `gears` 与 `rules` 两域。

> **文本长度约束**：三段文本**各自独立限长**，不再有合计预算（UTF-8 编码，一个汉字 3 字节）：
> `ledTextTemplate1 ≤ 48` 字节、`ledTextTemplate2 ≤ 48` 字节、`ttsText ≤ 88` 字节。
> 单段超出即在解析阶段拒绝（回 `1001`），不会静默截断。
> 三段同时用满时帧长 191 字节，仍在 0x03 载荷上限 206 之内，因此可以放心各段用满。

## 8. 网关回应

### 8.1 命令应答

每条下行命令都会得到一条应答（信封见 §4.2）。`code = 0` 表示成功；非 0 表示失败原因，
`msg` 为对应英文短描述，详见 §13。

- 对 `cfg.set` 的**版本冲突**，应答 `code = 1002`，且 `data` 会带 `currentVersion`
  （平台据此更新本地版本后重发）；
- 对 `cfg.query` 的**应答过大**（超出单条发布上限 **4352 字节**），网关会回一条 `code = 1011` 的小应答，
  提示平台**改为按域查询**（见 §9.1）。

### 8.2 上行事件一览

| 事件 | 主题 | 触发时机 | data 主要字段 |
| --- | --- | --- | --- |
| `status.report` | `status` | 心跳周期（默认 30s，retained） | 见下方状态字段表 |
| `telemetry.report` | `telemetry` | 与心跳同周期，全量水位 | `sensors[]`、`effective` |
| `event.status_change` | `event` | 水位状态发生迁移 | `from` / `to` / `gear` / `levelCm` |
| `event.action` | `event` | 联动动作的真实执行结果 | `gear` / `trigger` / `results[]` |
| `event.device` | `event` | 绑定/解绑结果、设备在线/离线等 | `uid` / `devType` / `event` / `serial` |
| `ota.progress` | `event` | 升级进度变化 | `state` / `percent` / `targetVersion` |
| `event.buffered` | `event` | 网关掉线重连后补报缓存事件 | `events[]` |

**`status.report` 的 `data` 字段：**

| 字段 | 说明 |
| --- | --- |
| `online` | 网关在线状态（bool） |
| `fwVersion` | 固件版本 |
| `slot` | 当前运行槽位（`A` / `B`），A/B 双分区升级用 |
| `configVersion` | 当前配置版本号 |
| `rsrp` | 信号强度（dBm） |
| `uptimeSeconds` | 网关运行时长（秒） |
| `mode` | 当前规则模式（`auto` / `manual`） |
| `currentGear` | 当前档位 `0` ~ `3` |
| `currentStatus` | 当前运行状态（正常 / 预警 / 报警 / 失联等） |
| `sensorsOnline` / `sensorsTotal` | 在线 / 总数（液位传感器） |
| `devicesOnline` / `devicesTotal` | 在线 / 总数（联动设备） |

> 共 **13 个**字段（上表按实际顺序）。平台解析请允许未知字段，便于后续扩展。

**`telemetry.report` 的 `data` 字段：**

```json
{
  "sensors": [
    { "uid": "21....", "levelCm": 12.3, "rawMm": 123, "batteryPercent": 87, "rssi": -70, "ts": 1690000000 }
  ],
  "effective": { "levelCm": 12.3, "status": "Warning", "gear": 2 }
}
```

- 每条遥测为**全量**：把当前所有在线且启用的液位传感器一并放入 `sensors[]`；
- `sensors[].ts` 为该台上报**发生时**的时间戳（多台上报时刻不一定相同）；
- `effective.levelCm` 为有效水位，`effective.status` / `effective.gear` 为对应状态与档位。

**`event.action` 的 `data`**：`{ "gear": N, "trigger": "auto|manual|failsafe", "results": [ { "uid": "...", "code": 0 } ] }`。

**`event.buffered` 的 `data`**：`{ "events": [ <完整事件对象>, ... ] }`。补报的每条事件**保留其原始
`event` / `msgId` / `ts` / `data`**，`ts` 为事件**原始发生时刻**，不会被改写成重连时刻。

### 8.3 断线补报

网关在掉线期间会把事件与逐条水位上报**缓存**在本地；重连成功后，经 `event.buffered`
**分批补报**（每批最多 16 条，`data.events` 中逐条为完整事件对象）。
平台按 `event.buffered` 的实际到达情况判断补报进度；`status.report` / `sys.query_status`
里的 `bufferedEvents` 字段已于 2026-11-12 移除，不再提供。

## 9. 网关参数修改

### 9.1 配置查询（`cfg.query`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sections` | string / array | 否 | 指定要查询的配置域。缺省 = 全部；可为 `"all"`、单个域名、或域名数组 |

应答 `data` 为**配置对象本身**（9 个域，见 §9.3）。

**注意：**

- 指定 `sections` 时只返回所列域；
- 应答超过单条发布上限时，网关回 `code = 1011`，**提示改为按域查询**；
- 应答中的 `network.password` 固定返回 `*****`，平台**不要**把该掩码原样回传 `cfg.set`。

### 9.2 配置修改（`cfg.set`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `expectVersion` | uint32 | 是 | 期望的当前配置版本；与网关当前 `configVersion` **不一致则回 `1002` 且什么都不改** |
| `effectiveMode` | string | 否 | `immediate`（默认）/ `reboot` |
| `sections` | object | 是 | 键为域名，值为该域的字段（可只给要改的字段） |

**应答 `data`：**

```json
{ "configVersion": 8, "applied": ["thresholds", "sensors"], "rejected": [] }
```

- **逐域事务**：每个域独立校验，合法域生效（进 `applied`），非法域被拒（进 `rejected`）**且其余域照常生效**；
- 所有合法域落盘成功后才递增 `configVersion`；
- `rejected` 非空仅表示「该域整域被拒」，具体原因需结合网关日志；
- 若 `sections` 中**不含任何已知域名**（键名全拼错），回 `1001`。

**`network` 域**：修改后**重启生效**，生效前当前连接保持不受影响；如需立即生效，可配合 `sys.reboot`。

### 9.3 配置域一览

| 域名 | 关键字段 | 说明 |
| --- | --- | --- |
| `system` | `gwId`、`password`、`timezone` | 网关标识、访问口令、时区（默认 +8） |
| `network` | `host`、`port`、`tls`（**暂不支持**，恒为 0）、`clientId`、`username`、`password`、`keepAliveSeconds`（30~300，默认 60）、`reconnectMinSeconds` / `reconnectMaxSeconds`、`statusIntervalSeconds`（10~600，默认 30） | MQTT 连接参数、心跳周期；**重启生效** |
| `sensors[]` | `uid`、`name`、`reportPeriodSeconds`（5~3600，**默认 300**）、`lowBatteryPercent`、`offlineTimeoutSeconds`、`enabled` | 液位传感器绑定与采集参数；失联判定 = `reportPeriodSeconds × 3`（默认即 900s） |
| `thresholds` | `alarmCm` > `warningCm` > `resolveCm`、`minChangeCm`、`eventMinIntervalSeconds`、`confirmCount`（1~10） | 分级阈值与防抖 |
| `gears[]` | `gear`（0~3）、目标设备、`soundMode`（0 关 / 1 常亮 / 2 慢闪 / 3 快闪）、LED 显示与文本、`ttsText` | 各档位联动动作定义 |
| `devices[]` | `uid`、`name`、`type`（只读）、`volume`（0~100）、`flashMode`（0~3）、`enabled` | 联动设备绑定与个性参数 |
| `rules` | `mode`（`auto` / `manual`）、`sensorOfflinePolicy`（`keep` / `alarm` / `off`）、`manualTimeoutSeconds` | 自动/手动模式与失联策略 |
| `ota` | `fwVersion`（只读）、`upgradePolicy` | 固件版本与升级策略 |
| `meta` | `configVersion`、`crc32`、`updatedAt` | 系统维护字段，**平台只读** |

> 各字段的具体取值范围以网关配置校验为准；`configVersion` 每次有效变更递增。

### 9.4 设备参数修改（`sen.set` / `dev.set`）

- **参数**：`uid`（必填，须已绑定）+ 该域的可写字段；**给了的字段才修改**，未给的不动；
- `serial` 与 `type` 为**只读字段**（绑定/注册时确定）：若在命令中出现，回 `1001`；
- `sen.set` 修改 `reportPeriodSeconds` 时，网关会同时把新的上报周期下发给传感器本身；
- 通过 `cfg.set` 的 `sensors[]` 修改 `reportPeriodSeconds` 时，网关同样会把新周期下发给传感器（与 `sen.set` 一致）；
- 应答：成功 `code = 0`。

### 9.5 规则模式切换（`rule.mode`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `mode` | string | 是 | `auto` / `manual` |
| `manualTimeoutSeconds` | uint16 | 否 | 手动模式回归超时（秒）。**写入配置并落 Flash，永久生效**（不是"仅本次生效"） |

应答 `data.configVersion`。切回 `auto` 时网关会立即按当前水位重新评估。

### 9.6 恢复出厂（`sys.factory_reset`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `keepNetwork` | bool | 否 | 默认 `true`：保留 `network` 域，避免恢复后失联 |

其余配置域恢复出厂默认，`sensors[]` / `devices[]` 清空，`configVersion` 归零。
应答 `code = 0`，无 `data`。

## 11. 固件升级（OTA）

| 命令 | 参数 | 说明 |
| --- | --- | --- |
| `ota.start` | `version`（string）、`url`（string）、`size`（uint32）、`md5`（小写 HEX）均必填 | 发起升级，受理后不阻塞；进度经 `ota.progress` 上报 |
| `ota.query` | 无 | 应答 `data`：`state`（`idle` / `downloading` / `verifying` / `installing` / `failed`）、`percent`、`targetVersion` |
| `ota.abort` | 无 | 中止升级 |

**`ota.start` 返回码：**

| 情况 | code |
| --- | --- |
| 目标版本与当前版本相同 | `1006` |
| 已有升级在途 | `1006` |
| URL 非法 | `2001` |
| 暂存空间不足 | `1010` |

> **下载失败 / 校验失败不走返回码。** 这两类失败发生在 `ota.start` 受理之后，
> 网关通过 `ota.progress` 的 `state = "failed"` 告知平台（仅有 `state` / `percent` /
> `targetVersion` 三个字段，**不带 `msg`**）。原 `2002` / `2003` 两个码已删除。

| code | 含义 |
| --- | --- |

## 15. 注意事项

1. **幂等**：同一 `msgId` 在 60s 内重复下发不会重复执行，网关直接重放上次应答；重发时请沿用原 `msgId`。
2. **配置版本**：`cfg.set` 必须带正确的 `expectVersion`；冲突回 `1002` 且**不改动任何配置**，平台据 `currentVersion` 更新后重试。
3. **异步语义**：`sen.bind` / `dev.bind` / `sen.unbind` / `dev.unbind` / `dev.ctrl` 的应答 `code = 0` **仅表示已受理**，
   最终结果以 `event.device` / `event.action` 事件为准。
4. **`network` 域重启生效**，运行期不热切换连接；需要立即生效时配合 `sys.reboot`。
5. **应答过大**：`cfg.query` 携带全量配置可能超出单条发布上限，此时回 `1011`，请按 `sections` 分域查询。
6. **敏感字段**：`cfg.query` 中的 `network.password` 固定返回 `*****`，请勿将其回传 `cfg.set`。
7. **断线补报**：网关在离线期间缓存事件与水位上报，重连后经 `event.buffered` 分批补报；补报事件的 `ts` 为**原始发生时刻**。
8. **掉线通知**：需感知网关掉线，请额外订阅 `rt/gw/{gwId}/lwt` 主题。
9. **设备标识**：设备 `uid` 为 **13 字节（26 位十六进制）** 唯一 ID，**首字节标识设备类型**（`11` 网关 / `21` 液位传感器 / `31` 声光报警器）；早期对接使用的 3 字节设备 ID **已不再支持**。
10. **TLS**：**当前版本暂不支持 TLS**，网关以明文方式连接 MQTT 服务器。
