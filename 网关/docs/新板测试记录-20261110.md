## 2. 问题清单

### P1（已修，需评审）配置 CRC 依赖"重新序列化"的 JSON
- **现象**：烧入新增了 `gears[].voice` 的固件后，两个配置区都 `code=4`(CFG_ERR_CRC) → 回落出厂默认，现场 `configVersion=97` 的配置全丢。
- **根因**：`config_store_calc_crc()` 是把配置**重新序列化**后算 CRC，再与上次存盘时算的 CRC 比对。序列化结果只要变一个字节（新增字段/改顺序/改格式），旧配置必然判死。
- **临时修复**：`voice == 0` 时**不写进 JSON**（默认值省略），老配置的序列化结果逐字节不变 → 97 恢复。
- **风险仍在**：以后任何新增字段（默认值非 0 时）或序列化顺序调整，都会再次清空现场配置。**建议**：把 CRC 改成覆盖 Flash 里实际存的 JSON 字节，或给配置加 `schema` 版本号做迁移。

### P2 启动横幅的日期时间是 `app_boot.c` 的编译时间
- 板上跑的是 19:40 链接的代码，横幅仍显示 `Nov 10 2026 17:28:42`（只有 app_boot.c 重编才会变）。
- **建议**：横幅加构建号/短哈希（如 `b20261110-1940`），避免现场误判版本。

### P3 现场切槽没有简单办法
- 板上 `active=B` 时，只烧 A 槽**不生效**（引导仍跳 B）。本次是手工往 META 追加一条 `active=A` 的启动记录才切过去。
- **建议**：加调试命令 `#switch A|B`（写启动记录并复位），或在手册里写明用 J-Link 改记录的具体步骤。

### P4 两台声光都判离线（待确认硬件）
- `dev.query`：`310000...116178` 与 `310000...116C78` 均 `online:false`；

- **待确认**：这两台声光今天是否通电？若未通电属正常；若已通电，需查 0x09/0x03 无应答原因（天线/配对值/固件）。

## 4. 第二轮：外挂 Flash / 电池 / 液位数据（2026-11-10 19:55）

### 4.1 外挂 SPI Flash —— 全部通过 ✅

| 测试 | 命令 | 结果 |
|---|---|---|
| 识别 | 启动日志 | `JEDEC=EF 40 17, W25Q64(8MB), SPI1 7MHz(分频码=3)` |
| 分区表 | `#flash info` | META 64K / CFG 64K / EVENT 2M / TELEM 3M / LOG 1M / OTA 512K / FW_FACTORY 1M + SPARE |
| 读写自检 | `#flash selftest` | `SPARE @0x7B0000: 擦 -> 写 64B -> 读回比较` **通过** |
| 格式化 | `#flash fmt` | `META 已格式化(seq=1)`，`自检通过` |

⚠️ **但业务还没用上它**：`xf_store_init()` 只在启动时初始化，`event_cache` / `telemetry_cache` 仍然是纯 RAM（256 条 / 128 条）。外挂 Flash 的 EVENT/TELEM/LOG 三个环目前**没有任何业务写入**（全工程搜不到除 boot/console 外的调用点）。要做"断网大数据量缓存"还得把缓存层接过去。

### 4.2 电池电量检测 —— 只有模组自测，没有网关 ADC

- `#vbat` → `模组自测供电 = 4226 mV`；`STAT` 里 `VBAT=4226mV`。
- 代码注释（app_console.c:175）明确：**VBAT 是 4G 模组自己的 ADC 测的供电**，不是网关板载的电池采样。
- 当前**没装电池**，读数是适配器电压 ~4.2 V，符合预期。
- `telemetry` 里 `sensors[].batteryPercent` 是**液位设备自己上报的电量**（当前 52%），与网关供电无关。
- ⚠️ 结论：**网关自身没有电池电压/电量检测硬件通道**。若产品要求"市电断开切电池"的检测，需要新增 ADC 分压采样（硬件 + 驱动），现有代码做不了。

### 4.3 液位恒为 0 + 设备时间不对（设备侧问题）

从 0x02 帧解出：`level_mm=0, bat=52%, 设备自报时间=11-04 12:08`（实际 11-10 19:58）。

- **level=0 是液位设备自己发出来的**（帧里 level_mm 就是 0），网关只是转发；`measureMode=level` 时不换算。
  → 要查设备侧的安装高度/校准/测距配置。
- **设备 RTC 不对**：比实际慢 6 天多，且两次抓包之间跳变异常（11-03 10:37 → 11-04 12:08）。
  → 网关有 0x01 校时（下发 6 字节时间），要确认这台液位是否支持/是否收到过。
- `#offline` 诊断：213606…17C42 上报周期 90s、阈值 270s、最近上报正常；213606…12D49 从没上报（未通电）。

## 5. 第三轮：event/telemetry 缓存接外挂 Flash（2026-11-11 00:0x）

### 5.1 做了什么

| 层 | 改动 |
|---|---|
| `xflash_store` | 新增 **数据环**：记录头(magic/len/seq/crc) + 负载，**固定 64 B 槽**；`xf_ring_push/peek/pop/used/dropped/poll/flush/format_all` |
| `event_cache` | RAM 环(256 条)满时，最旧一条 **溢出到 EVENT 环**（不再丢）；补报成功一条后自动从 Flash 拉一条回 RAM |
| `telemetry_cache` | 同上（TELEM 环，128 条） |
| `app_boot` | 开机把 Flash 环里"没补报完"的记录拉回 RAM（`*_cache_flash_recover`） |
| `app_loop` | 1 s 节拍调 `xf_ring_poll()`，把 head/tail 落 META（空闲 1 s 后写一次，不每条擦 META） |
| `app_console` | 新增 `#flash ring` 自检：写 3 条 → 读回比对 → 环恢复空 |

外挂 Flash 不在时整条链自动退化：`xf_ring_*` 返回 false，缓存行为与以前完全一致（丢弃 + dropped 计数）。

### 5.2 主机测试抓到的 3 个真缺陷（都已修）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 记录读回 crc 不符，坏字节正好落在 4 KB 边界 | 记录负载 **跨扇区**，下一条进入新扇区时先擦除，把上一条尾巴擦掉 | 改为固定 64 B 槽，天然不跨扇区 |
| 2 | tail 走过"环尾空隙"读到上一轮旧记录 | 变长记录换行留下的空隙被算进 used，tail 一路走过去 | 空隙从 used 扣除；最终固定槽彻底消除 |
| 3 | 环正好写满时，擦新扇区把 tail 一侧的活数据擦掉 | 空间判据只保证"空 1 个槽"，没保证"空一个扇区" | 进新扇区前必须留出整 4 KB（`free_arc >= 槽 + 4 KB`） |

|---|---|---|---|---|
| EVENT | 2 MB | 64 B | ~32,700 | 断网期间事件 |
