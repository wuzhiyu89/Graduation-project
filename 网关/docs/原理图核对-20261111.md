## 2. 两处需要改的地方

### 2.1 RS232_EN 的语义搞错了（会真出问题）

原理图（第 6 页）：
```
VBAT_3V7 ── U11 XC6219B332MR ── 232_3V3 ── U12 SP3232EEN 的 VCC(16)
              pin3 = CE ← 232_EN
```
**`232_EN` 是 232 那一路 3.3V LDO 的使能（高有效），不是收发方向。**

而 `bsp_uart.c::rs232_send_bytes()` 把它当"发送方向"用：

```c
GPIO_SetBits(RS232_GPIO_PORT, RS232_EN_PIN);   /* 以为是"切到发送" */
... 发完 ...
GPIO_ResetBits(RS232_GPIO_PORT, RS232_EN_PIN); /* 以为是"切回接收" */
```

拉低 = **把 SP3232 整个断电**。后果：

1. 平时（不发数据时）232 收发器没电，**收不到任何数据**；
2. 每次发送前才上电，SP3232 的电荷泵（C1+/C2+/V+/V-）要重新建立，
   头一两个字节电平不够，对方看到的可能是乱码；
3. 发完立刻断电，紧接着对方回的应答正好撞在断电窗口里，丢掉。

SP3232 是**全双工**收发器：T1IN(11)←RS232_TX、R1OUT(12)→RS232_RX，
**根本没有方向脚**（DE/RE 那套是 485 才有的）。所以正确做法是：

- `RS232_GPIO_Init()` 里把 PA2 拉**高**（上电），之后一直保持；
- `rs232_send_bytes()` 里删掉那两次翻转，只发数据。

目前没暴露的原因：`serial_proto` 里 RS232 只初始化、协议待定，还不收数据。
一旦接上 232 输入（比如触摸屏 `$TP` 帧），这个 bug 立刻表现为"发得出去、收不回来"。

### 2.2 电池采样脚：代码 PA7，原理图 PC3（且测的不是电池）

**第一层：脚号不对。** `power_mgr.c::pwr_adc_init()`：
```c
g.Pin = GPIO_PIN_7;                        /* GPIOA */
ADC_ConfigRegularChannel(ADC2, ADC2_Channel_02_PA7, ...);
```
但 PA7 在原理图上是 **SPI1_MOSI**（外挂 Flash 的 MOSI），BAT_AD 在 **PC3(pin 11)**。
对应宏是 `ADC2_Channel_09_PC3`（`n32h47x_48x_adc.h:570`）。

如果就这么接上去，`pwr_adc_init()` 会把 PA7 配成 `GPIO_MODE_ANALOG` ——
**SPI1 的 MOSI 就没了**，外挂 Flash 立刻写不进去，
而新的"Flash 即队列"架构会静默把每条待补报记录判为失败丢弃（只涨 `dropped`）。
这就是一颗定时炸弹：现在不响，只因为 `pwr_init()` **没有任何调用点**（见 §3）。

**第二层：BAT_AD 量的其实是 5V 输入，不是 3.7V 电池。** 原理图（第 2 页）：
```
VCC_5V ── R249 100kΩ ──┬── BAT_AD ── (PC3)
                       │
                    R250 100kΩ
                       │
                      GND        C213 100nF 并联
```
图上原文标注 **"0~5V = 0~2.5V"** ⇒ 分压比正好 1/2，`PWR_BAT_DIV_X100 = 200` 是对的。

但被测对象是 **VCC_5V**（220V 适配器 / 太阳能板那一路），
锂电池 `VBAT_3V7` 在 TP4056 的 BAT 脚后面，**ADC 根本看不到**。
所以 `PWR_BAT_CUT_MV 3500`（"低于 3.5V 断电"）这个策略在当前硬件上不成立：

- 5V 输入掉到 0 时读到 0，会被判成"电池 0V"→ 立刻断电，而电池其实还有电；
- 电池真快没电时（3.5V），5V 那一路读数跟电池无关，判不出来。

要真正测电池，硬件上得从 `VBAT_3V7` 再引一路分压；不改板的话，
这个 ADC 只能当"外部 5V 是否在位"用，不能做低电保护。

## 3. `power_mgr.c` 整份是死代码

```c
/* power_mgr.c:5  本文件只提供接口, 不接 main(见 power_mgr.h 的接入说明) */
```
全工程 `pwr_init()` / `pwr_bat_sample()` **无任何调用点**。所以现在：

- 电池电压没人采（`bat` 字段靠别处填或恒 0）；
- 232/485 的 EN 供电管理没生效（但 `bsp_gpio.c` 自己已经把 485 EN 拉成使能了，所以 485 能用）。

接入前必须先把 §2.2 的 PA7→PC3 改掉，否则一接上就打断外挂 Flash。

## 4. 原理图澄清的几件事（以后排障直接查这里）

| 事项 | 板上事实 |
|---|---|
| **485 的 EN 是电源使能** | `485n_EN` 接 `XC6219B332MR` 的 CE（pin3），高=供电。**不是收发器使能**，拉低=整个 485 口没电（收发都不行）。代码现在始终拉高，是对的。 |
| **485 的 DE/RE# 是短接的** | SIT3485ESA 的 DE(3) 和 RE#(2) 并成一个节点，由 `485DIR_x` 一根脚经 R6/R5(1kΩ) 驱动。DIR=高→DE高+RE#高=发送；DIR=低→两者都低=接收。代码的"一根 DIR 切方向"是对的。 |
| **485 有"自收发"选项** | 每路都有 R47/R1（自收发）与 R6/R5（单片机控制）**二选一**。若产线贴的是 R47，MCU 的 DIR 脚**完全无效**，靠 TX 电平自动切换方向。排查"DIR 切了没反应"先看贴的是哪颗。 |
| **232 没有方向脚** | SP3232 全双工，T1IN/R1OUT 直连。`232_EN` 只控供电（见 §2.1）。 |
| **4G 电源是 P-MOS** | `4G_RST`(PA8) → Q2 `AO3401A` 栅极，源极 `VBAT_3V7`、漏极 `VCC_4G`，R65 1k 串栅极、R80 10k 上拉。**低电平导通=上电**，与固件 `G4_PWR_SW_ON_HIGH=0` 一致。 |
| **4G 串口有电平转换** | UART0 经 U13 `MS4553S`（VCCB=3.3V / VCCA=1.8V）双向转换后接 `4G_TX/RX`。所以 MCU 侧是 3.3V，正常。 |
| **USB_HS 是接 4G 模块的** | PB14/PB15 经 R12/R14 **0Ω** 到模块 `USB_DM/USB_DP`。不是对外 USB 口，也不是 USB 主机。 |
| **4G 模块型号** | `ML307R-DL`（48 pin）。有 `DBG_RXD/DBG_TXD`、`WAKEUP_OUT`、`BOOT_MODE`、`PWR_ON/OFF` 等脚。 |
| **充电** | TP4056，PROG=R11 3kΩ ⇒ 充电电流 1200/3k ≈ **400 mA**。`CHRG#`/`STDBY#` 开漏低有效 → `BAT_CHRG`/`BAT_STDBY`。 |
| **两路电源输入** | CN5 4P：1=220V 转 5V（配小电池）、2=太阳能板 5V（配大电池），经 SS34 汇到 `VCC_5V`。 |
| **SIM 有两个卡座** | `CARD1`（小卡/nano）+ `CARD2`（贴片卡）**并联在同一组 SIM 信号**上（`SIM_VDD/RST/CLK/DATA`），`SIM_DATA` 有 R7 10k 上拉到 `SIM_VDD`，C12 100nF、C13 30pF。**没有 SIM 检测脚接到 MCU**。 |

> 关于"SIM 卡读不到"：两个卡座并联是常见隐患 —— 空卡座的触点悬空会给
> `SIM_DATA/CLK` 加一段寄生电容和不确定电平。可以先只贴/只插一个卡座，
> 另一个的焊盘不装，排除并联影响；同时用示波器看模块 `SIM0_CLK` 有没有波形
> （没波形说明模块根本没认到卡，问题在卡座侧；有波形但应答错说明是信号质量问题）。

## 5. 这份表是怎么来的

原理图 PDF 没有 ToUnicode，但文本用的是 `UniGB-UCS2-H`（码点即 Unicode）
加一路 `WinAnsiEncoding` 的 Arial，所以用标准库（zlib 解 FlateDecode + 按 `Td/Tm`
坐标还原行）就能完整取到中文和网络名。引脚表是按"引脚名所在行 → 正上方 3.6pt
的引脚号 → 该号外侧最近的网络名"重建的，已用 `PA4=SPI1_CS`、`PC3=BAT_AD`、
`PB12/PB13=BAT_CHRG/STDBY` 等已知项交叉验证。
个别行（PC0/PC1/PC2、PB7）的网络名受晶振说明文字干扰，已按"未接"处理。
